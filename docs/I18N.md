# English and Catalan interface

Supplier Evaluation uses **English source strings** and standard Odoo 18
translations. The Catalan catalog is `addons/supplier_evaluation/i18n/ca.po`,
loaded for Odoo's `ca_ES` language. The release remains **18.0.1.3.0**.
These changes require an authorized module upgrade in each deployment; editing
the repository does not migrate stored views/translations in existing databases.

## User experience

| English | Catalan |
| --- | --- |
| Supplier evaluation | Avaluació de proveïdors |
| OTD evaluation | Avaluació OTD |
| OTD below 50% | OTD inferior al 50 % |
| No data | Sense dades |
| View evaluated lines | Veure línies avaluades |
| Confirm renegotiation | Confirmar renegociació |
| On time / Late / Unknown | Puntual / Amb retard / Desconegut |

Install/activate Catalan using Odoo's standard language management and select
Catalan in the user's preferences. Reload the web session after changing the
language. The English route is **Purchase → Supplier evaluation → OTD evaluation**;
the Catalan route is **Compres → Avaluació de proveïdors → Avaluació OTD**.

On a **separate test database** with a configured Odoo installation, translations
can be loaded together with the module upgrade:

```sh
odoo-bin -c /path/to/test-odoo.conf -d supplier_evaluation_otd_test \
  -u supplier_evaluation --load-language=ca_ES --i18n-overwrite \
  --stop-after-init --no-http --max-cron-threads=0
```

`--i18n-overwrite` replaces customized translations; use it deliberately on a
copy and retain local overrides if maintaining a customized deployment.
No permanent database upgrade is performed by preparing these files.

## Translation coverage and maintenance

The template `i18n/supplier_evaluation.pot` contains **167 source entries**;
`i18n/ca.po` supplies a nonempty translation for every entry, without fuzzy or
obsolete entries. Coverage includes:

- Menus, action names, view headings, filters, buttons and explanatory text.
- Field labels and help, including meaningful explicit labels for custom
  fields previously shown with auto-generated names.
- OTD states, revision types, attribution choices and wizard warnings.
- Access/validation errors, SQL constraint messages and model descriptions.
- The app's name, summary and description. These three metadata entries use
  the standard `base.module_supplier_evaluation` external identifier; retain
  them when regenerating the module's translation export.

Python messages use Odoo `_()`; field labels, literal selection labels and XML
view terms use standard automatic extraction. Translated HTML preserves the
original technical attributes. Business names, demo records, stored selection
keys, model/field names and XML IDs are not translated or renamed.

To maintain the catalog, export the module's terms with Odoo's standard
translation tools, merge new entries, retain the three module metadata entries,
and rerun local catalog tests and real Odoo tests. No third-party runtime
translation library or JavaScript has been added.

## Validation — 2026-10-30

- **138 integration cases passed**: the 135 existing cases plus three tests
  for bilingual menus/actions/filters/fields/states, the renegotiation wizard
  and messages, and identical OTD results after language switches.
- **47 local tests passed**, including three catalog/markup/coverage checks.
- Chromium passed independently in `en_US` and `ca_ES`, covering all ten demo
  suppliers, sort/filter, no-data rendering, number formatting, drilldown,
  preservation of the standard Contact form and the renegotiation wizard.
- Both languages returned 10%, 20%, …, 100%; Supplier 05 returned 20 evaluated,
  10 on time, 10 late. The 200 captured purchase lines, 300 captured stock moves
  and 150 evaluated receipts match the archived input records exactly.
- Production AST comparison against `78e17c6` found only label/message changes
  and added translation wrappers. Security files, technical model/field names,
  XML identifiers, domains, formulas and stored selection values are preserved.

The first run exposed an assertion still expecting Catalan source text; it was
updated to English and dedicated bilingual assertions were added. The isolated
integration runner was also corrected to retain its original filestore across
one-off containers; the final run has no missing-filestore diagnostics.

All validation used fresh or restored **temporary databases**. The fictional
dataset came from an already validated local backup; the generator was not run.
Browser-only fixtures create incomplete purchase orders to open the wizard and
cancel it, without changing captured observations. Temporary services are
stopped and retained after verification. No permanent Odoo service or database
was updated or restarted.

Reviewed fictional screenshots are included in the main README (English) and
in `docs/screenshots/supplier-dashboard-ca.png` (Catalan). Detailed raw logs,
hashes and intermediate screenshots remain in ignored local backup directories.

## Limitations

Only English and Catalan are supplied. Other languages fall back to English
for this module's terms. Existing custom translations may need merging after
the original language changes from Catalan to English. Core Odoo translations
are supplied by Odoo, not duplicated here; business values such as a supplier's
own language remain unchanged. Dates and decimals follow the selected locale.
